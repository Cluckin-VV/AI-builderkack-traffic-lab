## Recording preflight

1. Capture a dedicated public-demo browser window only, with no inbox, other tabs, notifications, credentials or account menus in frame. No microphone required for the first footage pass.
2. Warm the free instance before recording. Read `/health` and record actual identity; stop if it differs from the intended code deployment. Do not conceal a different build behind an old caption.
3. Use 1920x1080 or 1600x900 if available, readable UI scale, H.264 MP4, 24–30 fps. These are production preferences, not competition requirements.
4. Inspect the existing scene. It is shared by visitors; do not reset the service or remove other visitors' buses merely to obtain an empty scene. Use `n → n+1`, not an assumed `0 → 1`.
5. Before the take, use normal command controls to make the light green and existing buses moving if necessary. All preparation must also go through the guarded pipeline. If another visitor interferes, label a local isolated take honestly instead of presenting it as public footage.
6. Keep source footage. Trim idle waits, but keep each submitted command and its resulting status together. Label edited footage; never splice different before/after states into a supposed single transaction.
