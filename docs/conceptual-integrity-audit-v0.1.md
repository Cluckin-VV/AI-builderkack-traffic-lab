## 4. 绕过验证器的状态修改

**待验证。** 当前工作区没有找到 `SceneState`、状态容器、场景 mutation 方法或 `Validator`。因此无法建立“状态写入点 → 调用者 → 是否经过 Validator”的证据图。

审计所需的最小证据应包括：

1. `SceneState` 的唯一写入口及其符号；
2. `Validator` 的返回结果类型及调用位置；
3. 所有 `SceneState` mutation/assignment 的交叉引用；
4. Renderer 是否持有可写状态引用。

## 5. 最小修复建议

当前不建议修复代码，因为目标原型代码未出现在审计范围内。最小、非功能性处理是：

1. 将 AI Builder 原型源码放入当前仓库或明确其实际路径；
2. 为五个核心概念各指定一个定义文件和一个公开边界；
3. 只保留一条编排入口：`User Command → SceneCompiler → Candidate SceneAction → Validator → SceneState Update → Renderer → Event Log`；
4. 为状态写入点建立可检索的唯一符号；
5. 为未知指令建立明确的拒绝结果，并要求拒绝路径不产生 `SceneState` mutation；
6. 让 Event Log 记录 command、candidate action、validation result、state change 和 render result 的关联标识。

这些是后续实现约束，不是本次新增功能。

## 6. 暂不应该加入的技术

在核心链路尚未被文件证据固定前，以下功能均拒绝加入。每项均给出重新评估条件：

1. **FastAPI**：拒绝。当前没有稳定的应用边界或 HTTP contract。重新评估条件：核心执行链已在本地代码中闭合，并明确需要外部 HTTP 调用。
2. **数据库**：拒绝。当前没有持久化需求或事件查询模型。重新评估条件：明确需要跨进程/跨重启保存 `SceneState` 或 Event Log，并先定义 schema。
3. **Redis**：拒绝。当前没有并发队列、共享缓存或分布式锁证据。重新评估条件：经测量确认单进程内存模型无法满足已定义的并发需求。
4. **LangGraph**：拒绝。当前没有多节点运行时、恢复语义或图状态需求；目标链路仍是固定线性链。重新评估条件：出现可证明的分支/循环/暂停恢复需求，且普通编排不足以表达。
5. **RAG**：拒绝。当前没有知识检索边界、文档索引或召回质量指标。重新评估条件：某条已定义的 SceneCompiler 输入明确需要外部知识，并有离线评测集。
6. **真实 LLM**：拒绝。当前连编译器、动作协议和验证器的本地契约都未被证实。重新评估条件：确定性编译/验证测试先通过，并明确 LLM 只生成候选 `SceneAction`，不得直接写状态。
7. **插件/工作流平台接入**：拒绝。当前没有稳定事件协议或外部副作用边界。重新评估条件：核心事件日志与错误语义稳定，并有明确的集成用例。
