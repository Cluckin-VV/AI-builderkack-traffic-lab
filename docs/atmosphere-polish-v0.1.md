# TransitLab 光影、天气与工作台润色 v0.1

日期：2026-10-04。范围：现有浏览器场景的表现层、画面控制、性能测量及回归验证。未修改交通控制器、SceneState、解析协议或付费模型调用；未提交、push、部署。

## 参考与证据边界

用户希望参考三段视频，尤其古寺视频，提升到接近 GTA V 高画质的视觉质感。当前提供的是抖音喜欢页截图，不是视频文件或单条公开链接。浏览器尝试读取失败，**没有实际观看三段视频**；不能判断视频的动态光影、真实帧率、技术栈或是否为离线渲染。

仅从古寺封面能读到的美术倾向：暖色建筑焦点、较暗的周边衬托、前中后景层次、建筑细节和环境光的统一。可迁移到城市路口的是冷暖光关系、清晰主体、阴影层次和湿路受控反射，而不是复制古寺题材。草地封面的高亮度不能直接用作信号灯曝光参考。封面标题中的模型名称或能力不作已验证事实。

DLSS 是专门的引擎集成，本项目仍是 Three.js WebGL 渲染，**没有 DLSS、帧生成、光线追踪或 GTA 同等级物理引擎**。不能把画质档位、较低像素密度或插值说成 DLSS4。[NVIDIA DLSS 编程指南](https://raw.githubusercontent.com/NVIDIA/DLSS/main/doc/DLSS_Programming_Guide_Release.pdf)

## 已实现

- 工作台改为石墨蓝黑基调，保留黄色主操作和青色验证反馈；调整侧栏宽度、标题、画面占比及长事件的溢出处理。
- 自然日光、金色时刻、蓝调暮色三个表现层预设；太阳方向、色温、天空和路灯同步改变，不改后端状态。
- 程序化分层云、太阳光晕、距离雾化；晴雨雪雾以归一化权重平滑过渡，暂停或后台恢复不会一次跳过天气动画。
- 雨滴改为细线；雪花改为圆形粒子；积雪面保留独立显隐控制。修复静态批处理吞并积雪面、导致晴天仍有白色覆盖的问题。
- 湿路降低粗糙度和底色，反射采用视角相关强度：俯视弱、低角度强；弱波纹和有限模糊。修复早期测试中的亮斑/迷彩图案。
- 十字路口两条共面道路共享一次反射捕获，避免互相递归渲染；环境反射只在天气或光照稳定后更新并释放旧目标。预过滤参数修正，清除相关警告。[Three.js PMREM 文档](https://threejs.org/docs/pages/PMREMGenerator.html)
- 信号灯发光材质绕开 tone mapping，红、黄、绿保持可辨认；不修改信号组和放行规则。
- 流畅、均衡、精细三个质量档。流畅档关闭平面反射、降低阴影和粒子预算；交通逻辑完全相同。
- UI 显示实际帧间隔算出的 FPS；tooltip 包含 p95 和 >250ms 卡顿数。可见状态下的长帧纳入统计，后台节流时间不冒充前台渲染性能。
- 天气按钮仍走预演→确认；没有直接修改 SceneState 的快捷通道。

## 尚未达成与下一步

1. **最没把握**：三个参考视频未读到；现有建筑、绿化、车身近景与用户目标仍有明显资产质量差距。
2. **最大遗漏**：GTA 质感不等于高曝光或湿路镜面；还依赖细节资产、法线/粗糙度、遮蔽、反射与镜头构图。当前无体积光、实时 GI、SSR 或路径追踪。
3. **三个月后可能失效**：继续叠加景物和反射，却不锁定资源/渲染预算，或只跑测试而不保留实际浏览器证据。
4. **建议的差异化功能**：同车辆种子的晴雪情景对比，显示等待时间并解释原因；本轮未实现，不冒充已有能力。
5. **提高协作效率**：补三个单条公开视频链接或原视频，指定最喜欢的 10–20 秒；同镜头、同硬件、同车数比较，而不是只说“更像 AAA”。

优先下一步：以一个近景街角为单位升级建筑立面、树木轮廓和材质细节，同时处理首次着色器编译卡顿，再做全屏 1080p、24 车、10 分钟稳定性验证。未达到 GTA/DLSS4 等效或获奖保证。

## 后续审计说明（2026-10-04）
